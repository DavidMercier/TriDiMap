# NanoMECommons Examples

This directory is a historical collection of notebooks and working examples
related to the NanoMECommons EU project. It is an archive of project workflows,
not a single installable Python package. The examples span Granta MI, materials
data extraction, nanoindentation mapping, EBSD correlation, and Power BI.

## Contents

| Location | Purpose |
| --- | --- |
| `Example_AIML_NI-Data_MappingClustering.ipynb` | Nanoindentation map extraction from Granta MI and exploratory clustering |
| `Ni-SiC.ipynb`, `Example_old.ipynb` | Earlier Granta MI and nanoindentation mapping workflows |
| `MaterialsProjectDataExtraction.ipynb`, `MaterialsProjectDataExtraction_Cleaned.ipynb` | Materials Project property extraction; retained as evolving notebook versions |
| `12_Preparing_data_for_Power_BI.ipynb` | Granta MI data access from Power BI Python queries |
| `Statistics_DB.ipynb`, `attributes_output.json` | Granta MI database/attribute exploration and a saved attribute listing |
| `BASF/` | BASF examples, spreadsheets, sample data, clustering analysis, and image workflow |
| `Exporters/` | Granta MI metadata/export notebook and example attribute data |
| `Examples/` | Granta MI functional-data import example |
| `nanoindentation-and-EBSD-data-correlation-main/` | R implementation, example data, and visualization assets for correlating EBSD and indentation maps |
| `nanoindentation-and-EBSD-data-correlation-main_python/` | Python counterpart with its own example data and assets |
| `outputs/` | Saved exploratory-analysis figures; these are outputs, not required inputs |

The two EBSD correlation directories are separate language-specific snapshots.
Their similar names and repeated figures are intentional; neither is a package
dependency of the other. The top-level `table_image.png` is generated by
`Statistics_DB.ipynb` when that notebook runs.

## Running Examples

Open the notebook of interest and select an environment that has that
notebook's dependencies installed. Dependencies vary by example and are not
captured by a shared environment file. Granta MI notebooks require the licensed
`GRANTA_MIScriptingToolkit` and access to the relevant server, database, and
records. Materials Project notebooks require `pymatgen`/`mp-api` and a local
Materials Project key configuration (`PMG_MAPI_KEY` in `~/.pmgrc.yaml`). Do not
put passwords or API keys in notebook cells or outputs.

Some notebooks are historical and may still contain machine-specific file
paths, rely on local files, or expect a particular working directory. Review
those paths and access permissions before running or sharing the examples.
Partner datasets and exported results should be shared only when permitted by
their data owners.

Jupyter checkpoint directories are editor-generated recovery copies and are
excluded from version control by the repository `.gitignore`.
